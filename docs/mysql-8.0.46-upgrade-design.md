# 8.0 升到 8.0.46 设计

授权：工作帖 `#e26e7163`。唯一执行人：白小纯。

`7c6d385931f2ef6c56d449bd30825b9981573cd5`。

曹伟拍板：先把 8.0 从 MySQL 8.0.35 升到 8.0.46，升完再做建表兼容。
建表兼容是第 2 步，这篇只覆盖第 1 步。

## 1. 现在是什么

GitHub 上的 `8.0` 不是一份完整的 Oracle MySQL 源码树。
它是 WeSQL 覆盖层：仓库里有 `sql/`、`storage/`、`cmake/` 等自己的目录，
再加一份打到上游的补丁
`patches/mysql-server-8.0.35.patch`（约 195KB，65 个上游文件）。

别人要编出能跑的 Server，需要：

1. 拿一份干净的 Oracle MySQL **8.0.35** 源码；
2. 把本仓库覆盖上去；
3. 再打 `patches/mysql-server-8.0.35.patch`。

打完之后，上游 `MYSQL_VERSION` 里是：

```
MYSQL_VERSION_MAJOR=8
MYSQL_VERSION_MINOR=0
MYSQL_VERSION_PATCH=35
MYSQL_VERSION_STABILITY="LTS"
WESQL_VERSION=0.1.0
```

`mysqld --version` 对外仍是 MySQL 8.0.35，后面带 WeSQL 0.1.0。
本机 KEEP 容器 `wesql-task27-v11` 和 `9.7` 现场都不属于这条线，不动。

## 2. 这次升完长什么样（用例子说）

今天：按上面三步，用 **8.0.35** 源码能编出 WeSQL。

升完：同样三步，改成用 **8.0.46** 源码，补丁文件改名为
`patches/mysql-server-8.0.46.patch`。`MYSQL_VERSION` 里
`MYSQL_VERSION_PATCH` 从 `35` 改成 `46`，`WESQL_VERSION=0.1.0` 保留。

中间的 8.0.36、8.0.37、……、8.0.45 不单独交货。
一次合到 8.0.46，不搞 11 次小版本发布。

`9.7` 已经是另一条长期分支，这条升级不合进 `9.7`，
也不把 `9.7` 上的 Server 改动直接贴到 `8.0`。

## 3. 这次做哪些

同一人从头做到自己验证完。先合这篇设计，再改代码。

1. 准备一份干净的 Oracle MySQL 8.0.46 源码，和新的覆盖/构建目录。
   不复用 8.0.35 的对象文件、安装目录、datadir、bucket 或旧验收结论。
2. 把现有 `mysql-server-8.0.35.patch` 往 8.0.46 上试打一遍。
   套得上的文件只当定位线索；套不上的文件列出冲突，按 8.0.46 的接口重写。
   65 个补丁路径里，版本号、CMake、启停、错误号、handler 接线这类地方，
   最容易和上游小版本对不上，优先看这些。
3. 覆盖层（`sql/`、`storage/`、`cmake/` 等）只改 8.0.46 真正编不过、
   链不上、启不来的接点。不为第 2 步提前改建表兼容。
4. 自己编、自己测：干净配置、编译、安装、
   `mysqld --version` 能看到 8.0.46 和 WeSQL 0.1.0、
   启动、SmartEngine 基本读写、同配置重启。
5. PR 合进 `8.0`。临时分支从 `8.0` 拉，合完再删这条临时分支。
   其他未合 PR 的分支不动。
